# v0.8.1 交互收口设计

## 目标

v0.8.1 不增加新的知乎能力，专注把“自动发现开发方向”的主流程变清楚。机会报告页从一张堆满按钮的卡片，调整为可理解的三步流程：选择/刷新数据源、查看候选机会、生成报告。

## 范围

### 机会报告三步向导

机会报告页顶部展示三步：

1. 数据源：本地缓存、浏览器会话、追踪、未读、工作台、研究项目。
2. 候选机会：按本地机会分排序并支持快速筛选。
3. 生成报告：使用当前 DSH provider/model，或复制 Agent prompt 兜底。

### 浏览器会话状态常驻

机会报告页显示浏览器会话状态：已选择 profile、已缓存线索数、上次读取时间、验证/读取按钮。Cookie 操作仍保持显式，只读，且不进入模型或导出。

### 缓存/刷新状态可见

内容工具条或机会报告页显示数据来源状态：本地缓存条数、后台刷新状态、最近更新时间。每个 tab 切换时已经先显示缓存/加载态，本轮补充用户可见的说明。

### 候选机会筛选

机会报告候选增加快捷筛选：全部、高优先级、新内容、追踪/未读、浏览器会话、工作台/项目。筛选只影响当前展示，不改本地数据。

## 不做

- 不改登录/浏览器 Cookie 安全策略。
- 不新增账号写操作。
- 不引入 embedding 聚类。
- 不自动定时生成报告。

## 验证

实现后运行 dashboard 脚本语法检查、`npm run check`、`git diff --check`，同步 runtime，提交 checkpoint。若整批稳定，发布 `v0.8.1` tag。

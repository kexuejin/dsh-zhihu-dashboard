# v0.7.0 机会发现设计

## 目标

把知乎面板从“收集内容的工作台”推进到“自动发现开发机会的雷达”。插件的核心价值不是复刻知乎客户端，而是从热榜、关注动态、追踪新增、收藏新增和工作台内容中发现值得本地开发的方向，输出可执行的项目/插件/工具创意。

## 范围

### 机会报告

新增“机会报告”tab，聚合已有内容来源生成候选机会列表。第一版不自动调用知乎直答，只生成本地评分、证据内容和可复制的 Agent 分析提示，避免无感消耗直答额度。

### 本地机会评分

每条候选内容基于轻量规则计算机会分：

- 来自追踪、未读或工作台待分析：加分。
- 命中偏好关键词：加分。
- 新内容或新收藏：加分。
- 点赞/热度较高：加分。
- 命中过滤规则：不进入候选。

评分只用于排序和提示，不宣称客观判断。

### Agent 报告提示

机会报告页提供“复制 Agent 报告提示”，把高分候选组织成结构化 prompt，要求 Agent 输出：今日值得关注方向、证据、可做成本地什么工具/插件/应用、风险与反方观点、下一步行动。

### 行动闭环

每条机会支持：加入待分析、加入研究项目、阅读原文。报告整体支持导出 Markdown/CSV，延续现有研究包机制。

## 不做

- 不自动定时生成报告。
- 不引入 embedding 或复杂聚类。
- 不自动调用知乎直答。
- 不自动创建代码项目或修改其他本地仓库。
- 不增加点赞、评论、关注、发回答等知乎客户端能力。

## 数据来源

第一版优先使用浏览器本地已有数据：

- `zhihu.workspaceItems`
- `zhihu.researchProjects`
- `zhihu.unreadItems`
- `zhihu.tracks` 的 `lastItems`
- 收藏夹和热榜/动态仍可通过用户切换对应 tab 刷新后进入缓存/工作台

## 验证

实现后运行 dashboard 脚本语法检查、`npm run check`、`git diff --check`，同步 runtime，提交 checkpoint，整批稳定后发布 `v0.7.0` tag。
